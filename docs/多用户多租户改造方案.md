# 多用户多租户改造方案

> 目标：把当前「本地单机 + CSV 单租户」系统，改造成**公有云 SaaS + 多用户多设备 + 多队多租户**的可商用产品。
> 本文给出：数据表怎么改、登录怎么做、成本与工期估算、迁移路径与风险。
> 关联决策：口径归属沿用现有 `SPORT_FOCUS`（已落地）；部署形态=公有云 SaaS；PIPL 暂搁置（上线前仍需补）。

---

## 0. 现状与目标差距

| 维度 | 现状 | 目标 |
| --- | --- | --- |
| 数据存储 | `data/*.csv` 三个文件，单租户 | 云数据库，按 `tenant_id` 隔离 |
| 用户 | 无账户体系，仅占位口令 `EFA_ACCESS_PASSWORD` | 多用户 + 角色 + 登录 |
| 访问 | 本机 `localhost:8501` | 公网 HTTPS + 域名，平板/电脑浏览器 |
| 隔离 | 无 | 每队只能看自己的数据（行级隔离） |
| 并发 | 单写端文件锁 | 数据库事务 + 连接池 |

---

## 1. 总体架构

```
用户（平板/电脑浏览器）
        │ HTTPS
        ▼
[云服务器] Nginx(反向代理/TLS) → Streamlit 应用（Docker 容器）
        │                              │
        │ 会话(cookie)                 │ ORM 查询（自动注入 tenant_id）
        ▼                              ▼
[托管 PostgreSQL] ← 备份 → [对象存储 OSS/S3]
```

要点：
- **Streamlit 无内建账户系统**，需自建登录页 + 会话管理（见第 3 节）。
- **租户隔离放在数据访问层**，所有查询强制带 `tenant_id`，不靠前端隐藏。
- CSV 不再作为运行时存储，仅作为**导入/导出格式**保留（兼容你现有 Excel 工作流）。

## 3. 登录与认证怎么做

### 3.1 推荐方案：自建轻量认证（可控、无第三方依赖）
1. **登录页**：Streamlit 页面，用户名 + 密码，提交后校验 `users.password_hash`（bcrypt）。
2. **会话**：校验通过写入 `st.session_state`（用户 ID、租户 ID、角色），并签一个 **HttpOnly + Secure cookie**（itsdangerous 签名），跨页面/刷新保持。
3. **统一闸口**：把现有 `utils.require_access_gate()` 从"单口令"升级为"查会话/验 cookie"，未登录跳转登录页。所有页面经 `inject_css()` 自动受保护（已铺好）。
4. **退出**：清 session + cookie。

### 3.2 备选方案
- `streamlit-authenticator` 第三方库：省事，但定制多租户/角色需改源码。
- OAuth / 企业微信 / 学校统一身份：适合机构客户，成本高，二期再说。

### 3.3 角色权限（最小够用）
| 角色 | 权限 |
| --- | --- |
| admin | 管本队用户、改常模、导入/导出、删除数据 |
| coach | 录入/编辑测试、查看分析、生成报告 |
| viewer | 只读查看与导出 |

> 所有数据操作在服务端校验 `role` + `tenant_id`，前端隐藏只是体验，不是安全边界。

## 4. 租户隔离怎么保证（关键）

- **自动注入**：ORM 层用"当前租户上下文"（从会话取 `tenant_id`），所有查询自动加 `WHERE tenant_id = ?`，开发时无法遗漏。
- **行级安全（RLS）**：PostgreSQL 开启 RLS 策略，数据库层面再兜一道，即使代码漏写也查不到别队数据。
- **导入导出**：CSV 导入必须指定目标租户；导出文件自动带租户标识，防止串队。
- **审计**：跨租户访问尝试记入 `audit_logs` 并告警。

---

## 5. 从 CSV 迁移到数据库的路径

1. **双写过渡期**：保留 CSV 导入/导出能力，新增数据库写入；旧数据用迁移脚本一次性导入。
2. **迁移脚本**：读三个 CSV → 建 tenant（你先建第一个队）→ 写 athletes/tests/standards → 用映射表把"运动员ID"换成 UUID。
3. **校验**：迁移后逐表比对行数、得分抽样重算一致，确认无丢列。
4. **回退**：保留原 CSV 与备份脚本；迁移失败可回滚到单机版。

## 6. 代码改动清单（按文件）

| 文件/模块 | 改动 |
| --- | --- |
| `config.py` | 新增数据库 URL、cookie 密钥等配置项 |
| `utils.py` | 数据访问层改为 ORM；`require_access_gate()` 升级为会话校验；`load_table` 等改为 DB 查询 |
| `app.py` + `pages/*` | 基本不动（已通过 `inject_css()` 统一挂载闸口） |
| 新增 `auth.py` | 登录/注册/会话/角色校验 |
| 新增 `models.py` | 数据表 ORM 定义 |
| 新增 `migrate.py` | CSV → DB 迁移脚本 |
| `reports.py` | 数据源从 DataFrame 改为 DB 查询，判定逻辑不变 |

> 好消息：评分算法（`calc_score` 等）与界面结构无需重写，主要改"数据从哪来"。

## 7. 成本估算（公有云 SaaS，按初期规模）

> 以下为国内主流云厂商参考价，按 1 个租户试点、10–50 用户估算，实际以选型报价为准。

| 项目 | 规格 | 月成本（元） |
| --- | --- | --- |
| 云服务器 | 2核4G / 5M 带宽 | 150–300 |
| 托管 PostgreSQL | 1核2G / 50G（或自建在服务器上省此项） | 100–300 |
| 对象存储（备份） | 100G | 10–30 |
| 域名 | .com/.cn 年费折月 | 5–15 |
| SSL 证书 | Let's Encrypt 免费 | 0 |
| 监控告警 | 基础免费额度 | 0–50 |
| **合计** | | **约 265–695 / 月** |

一次性：域名首年、备案（国内服务器需 ICP 备案，免费但需时间）、可能的商用常模授权（另计）。

> 降本：初期可把 PostgreSQL 装在同一台云服务器，省 100–300/月；用户量上来再拆。

| 阶段 | 工作 | 人天 |

| 1 | 数据库建模 + ORM 接入 + 配置项 | 2–3 |

| 5 | CSV 迁移脚本 + 校验 | 1–2 |

| 7 | 多角色/多设备联调 + 回归测试 | 2–3 |
| **合计** | | **约 15–22 人天（3–4.5 周）** |
