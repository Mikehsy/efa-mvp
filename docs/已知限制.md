# 已知限制（V1.0）

> 本文是交付范围的一部分：以下条目**不作为 V1.0 验收缺失项**，但使用时必须知晓。

## 1. 部署形态

- **单机 / 局域网单实例**：同一时刻只允许 1 处写入（单写端文件锁保护读-改-写）。多人同时录入可能造成后写覆盖前的体验问题，请指定一名数据录入员。
- **无账号与权限体系**：任何能访问该地址的人都能查看与修改数据。V1.0 以物理单机、`address = localhost`、内网防火墙白名单与操作审计替代；公网暴露不在范围内。
- 默认监听 `localhost`；局域网使用需把 `.streamlit/config.toml` 的 `server.address` 改为 `0.0.0.0` 并配置防火墙。
- CSV 存储适合本系统当前规模（实测 20000 条时加载约 1.0 s）；更大规模或多人写入需迁移到数据库（V1.1 评估）。

## 2. 评分与报告口径

- **示例常模**：`standards.csv` 的 270 组阈值是示意值，标注为「非专业常模，请按本队实测替换」。正式使用前必须替换并更新 `EFA_STANDARDS_VERSION`，否则报告结论不可用于选拔、诊断或训练决策。
- **标准变更会重算历史得分**：修改「04 评分标准」的任意阈值后，全部历史 `continuous` 得分自动重算，跨版本对比请先核对报告中的版本标记。
- 报告结论由内置规则基于已记录数据生成，**不构成医疗诊断或训练处方**；改善建议为通用示例，需教练结合专项、训练周期与运动员状态确认。
- 未配置阈值的组合不评分（显示 `—`），也不会进入不足项判断；样本量 < 10 条时结论仅作初步参考。
- FMS 的 0~3 原始分只用于风险、疼痛与左右不对称分析，绝不进入 0~100 得分体系。

## 3. 数据与功能边界

- 「运动项目」是写入时快照：修改运动员档案不会改动已有测试记录的项目归属，这是有意设计，用于按项目出具历史报告。
- 旧格式 7 列 CSV 可自动迁移（补列 + 推断运动项目）；推断不出的档案会标为「未填写」，需到「01 运动员管理」补全。迁移后 FMS 行的「测试类别」按旧格式统一标为「体能」，若从极旧备份恢复需人工复核。
- 数据文件被 Excel 打开时，写入可能因文件占用失败；此时页面会给出提示，请关闭 Excel 后重试。
- 无移动端适配、多语言、邮件推送、多人实时协同、AI 生成建议、SSO 与等保合规。
- 无内置数据库版本管理与字段级审计历史；审计日志记录的是操作，不保存逐字段旧值，需恢复旧值请用写前快照或整份备份。

## 4. 运行与兼容

- 实测环境：Python 3.12.10 / Streamlit 1.67.0 / Windows 11 / Chrome-Edge 内核。Python 3.11、Windows 10、Chrome 与 Edge 最近两版仍需按 `docs/测试与性能基线.md` 的兼容矩阵人工验证。
- `use_container_width` 已在阶段 4 统一替换为 `width`（依赖 Streamlit ≥ 1.50，已写入 `requirements.txt`），不再有弃用告警。
- 生产配置 `client.showErrorDetails = false`：浏览器只显示通用错误，完整堆栈写入 `logs/app.log`。
- 离线 wheels 包需在有网机器预先执行 `pip download -r requirements.lock -d vendor` 后才能用 `setup.ps1 -Offline` 安装。
- `pytest` / `ruff` 在当前离线环境不可用；回归测试用标准库 `unittest`（47 用例），静态检查以 `py_compile` + 人工评审清单替代。

## 5. 运维责任

- 快照与备份保存在本机，**没有异地容灾**；请按《部署与运维手册》每日把 `backups/` 复制到其他介质。
- 日志保留策略：单文件 5 MB 轮转、最多 10 份；审计与业务数据本身由使用者自行归档。
- 监控依赖 Windows 计划任务调用 `healthcheck.ps1`；若未配置计划任务，则只有手动探活，不会主动告警。
