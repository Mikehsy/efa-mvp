# 已知限制（云端 SaaS 版，2026-11-18）

> 本文是交付范围的一部分：以下条目不作为上线验收缺失项，但使用时必须知晓。
> 本版为云端重写版，替代原 V1.0 单机/局域网口径。历史决策见 `docs/决策记录.md`。

## 1. 部署形态与数据隔离

- **公有云 SaaS**：Streamlit Community Cloud + Supabase PostgreSQL，用户经浏览器在电脑/平板访问，无需安装。
- **按个人账号隔离（最终决策）**：数据按 `owner_id` 严格隔离，不同账号互不可见。**不做按队共享、不做角色权限（教练/管理员）**——这是业务方 2026-11-18 的明确决策，相关改造已取消。
- **单账号 = 单数据域**：若一个队有多名教练需协作，当前只能共用同一账号，或各自独立建档后手工导出交换；系统不提供账号间的数据授权与共享。
- **无 SSO、无等保资质**：认证为应用内用户名/密码（PBKDF2 哈希），不接入企业单点登录，未做等级保护测评。

## 2. 评分与常模口径

- **常模状态**：标准表 216 行（27 项 × 2 性别 × 4 年龄组，已取消大师组）。其中握力、坐位体前屈、静息心率、30米冲刺、Yo-Yo、引体向上、纵跳等 44 个组合已写入有出处的确认值（中国足协 2026 / 协和 2023 / 国家学生体质标准 / 临床规范）；**其余仍为示例常模**，标注「非专业常模，请按本队实测替换」，未替换前相关项目的报告结论不可用于选拔、诊断或训练决策。
- **跨人群套用**：确认值多来自中国青少年足球运动员、普通人群或学生样本，与专业队运动员并非同一人群，系统按"临时依据"使用并在来源中标注；正式队内常模到位后应替换。详见 `docs/NSCA常模摘录（带出处）.md`、`docs/剩余19项标准出处网络检索报告.md`。
- **Yo-Yo 模式**：15 岁及以下 IR1、16 岁及以上 IR2，数值不可直接比较；系统无独立模式字段，按年龄组隐含区分，跨年龄比较需谨慎。
- **计分口径**：三段式线性换算，低限线 = 0 分、达标线 = 60 分、优秀线 = 100 分；低于低限记 0、高于优秀封顶 100。标准表新增低限线，旧 10 列表在读取时内存推导兼容。等级分段：<60 待提升 / 60–74 达标 / 75–89 良好 / ≥90 优秀。
- **标准变更会重算历史得分**：修改任意阈值后，全部历史 continuous 得分实时重算；跨版本对比须核对 `STANDARDS_VERSION`。
- **未配置组合不评分**：显示「—」，不进入不足项判断；样本量 < 10 条时报告结论仅作初步参考。
- **FMS**：0～3 原始分只用于风险、疼痛与左右不对称分析，绝不进入 0～100 得分体系。
- **报告非医疗结论**：报告由内置规则生成，不构成医疗诊断或训练处方；改善建议为通用示例，需教练结合专项、训练周期与运动员状态确认。

## 3. 数据与功能边界

- **运动项目是写入时快照**：修改运动员档案不会改动已有测试记录的项目归属，这是有意设计，用于按项目出具历史报告。
- **标准组是写入时快照**：测试记录按测试当天的实足年龄定型（4 组）；之后修改出生日期不改历史标准组。取消大师组后，历史「|大师」快照在读取时内存归一为「|成年」，旧数据仍可评分。
- **出生日期**：新增/编辑支持手动输入任意年份（含 1992 年以前），20 岁及以上统一归成年组。
- **无移动端原生 App**：通过浏览器响应式访问，无独立 App、无离线缓存、无推送通知。
- **无 Email/短信推送、无多语言、无 AI 生成建议**。

## 4. 运行与兼容

- **实测环境**：Python 3.12.10 / Streamlit 1.67.0 / Chrome-Edge 内核。其他版本与浏览器需按 `docs/测试与性能基线.md` 的兼容矩阵人工验证。
- **云端免费层限制**：Streamlit Community Cloud 免费方案计算资源有限，页面每次交互会重跑脚本、短暂变灰；已通过连接池、会话缓存与读表缓存优化，但大批量导入仍可能较慢。
- **容器临时盘**：应用重启不保留容器本地文件；业务数据存 Supabase，但 `logs/*.log` 等文件日志重启即丢，关键合规事件已持久化到 DB 的 `consents` 表。
- **回归测试**：`unittest` 75 项（2026-11-18，三段式评分后），`py_compile` + 人工评审替代静态检查；测试覆盖见 `docs/测试与性能基线.md`。
- **技术运维保障**：DEV 已提供 `docs/上线运维保障方案.md`、`docs/每日巡检表.md`、`docs/备份与恢复演练记录模板.md`、`docs/安全事件应急预案.md` 与 `docs/观察期问题登记表.csv`；实际执行、证据留存与签字仍由运营方/运维承担。

## 5. 隐私合规与运维责任

- **PIPL 技术措施已落地**（知情同意、敏感信息单独同意、出境单独同意、撤回、注销、导出、去标识化留痕、政策版本化），但**法律义务未完成**：真实主体信息、法务审阅、PIA、出境合法路径、未成年人监护人同意留档、异地备份与应急预案仍需运营方完成，见 `docs/PIPL合规实施说明.md` 第八节与 `docs/上线前自检清单.md` E 节。任一未完成前不得宣称合规或正式商用。
- **异地容灾依赖运营方**：Supabase 项目需配置备份策略；免费层的容器临时盘不可依赖。
- **监控**：无自动告警探活；依赖 Streamlit Cloud 的应用状态页与运营方人工巡检。
- **无字段级审计历史**：审计记录操作，不保存逐字段旧值；写前快照与 DB 留痕用于追溯。
