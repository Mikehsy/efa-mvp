### 2-A 数据与业务（🔴 硬阻塞：无则无法正式使用）
1. **实测常模（270 组阈值）**

   - 格式：UTF-8 CSV（带 BOM 推荐），或直接在「⚙️ 评分标准」页逐项编辑保存。
   - 原因：当前为「示例常模 v0」，所有得分/达标率只是演示口径，**未替换前不可出具任何正式结论**。
2. **正式运动员名单**

   - 格式：UTF-8 CSV；先小批量试 1–2 条再全量。
   - 原因：页面需反映真实队伍；`运动员ID` 是关联所有测试记录的键。
3. **历史测试与评估记录**

   - 格式：UTF-8 CSV。

4. **运动项目 / 能力域口径确认**

### 2-B 安全与多用户（🔴 硬阻塞：影响数据隔离与合规）
5. **认证模型决策**
   - 需决策：单共享口令（现状占位）**还是** 多用户 + 角色（教练 / 管理员）？
   - 原因：直接决定代码实现；多用户需账户表、登录会话、权限校验。
6. **数据隔离 / 租户模型决策**
   - 需决策：单队自用（一份数据）**还是** 多队多租户（每客户独立数据、互不可见）？
   - 原因：商用交付给多个客户必须隔离；涉及数据目录/数据库schema设计，定错会大面积返工。
7. **隐私合规策略（PIPL）**
   - 需提供：运动员个人数据处理政策 —— 知情同意方式、数据最小化范围、留存期限、是否脱敏导出。
   - 原因：含姓名/出生日期/成绩的体能数据属个人信息，商用在中国需符合《个人信息保护法》；需你方法务/负责人确认，开发据此加留痕与脱敏。

### 2-C 部署与基础设施（需账号 / 权限 / 决策）
8. **部署形态决策**
   - 需决策：本地单机 / 内网服务器 / 公有云？
   - 原因：决定交付包形态（原生 / Docker / 服务化）、反向代理与运维方式；我方已备 Dockerfile 与脚本，等你定目标环境后出对应部署指南。
9. **公网暴露与域名 / HTTPS**
   - 需提供：若对外提供服务，需域名、TLS 证书、反向代理（Nginx/Caddy）方案；涉及外部平台/证书账号。
   - 原因：系统当前无认证体系，公网直暴露有泄露风险，必须叠加认证 + HTTPS + 反向代理（属开发需求，需在第 8 项后推进）。
10. **服务常驻方式**
    - 需决策：目标 OS（Windows 服务 / Linux systemd / 容器编排）。
    - 原因：决定常驻与开机自启脚本；影响监控探活（脚本已就绪）能否生效。
11. **备份异地存储**
    - 需提供：异地备份盘或对象存储（OSS/S3 等）账号与路径。
    - 原因：备份演练目前在本机；商用需异地容灾。

### 部署形态建议（面向社会商用）
- **推荐：公有云 SaaS** —— 云服务器 + 域名 + HTTPS + 反向代理 + 容器化（已备 `Dockerfile`）。多队多租户天然适合 SaaS 订阅模式，用户凭账号在平板/电脑浏览器访问，无需安装。
- **备选：私有化部署** —— 客户内网服务器，适合对数据出域敏感的专业队；交付 Docker 镜像 + 部署手册。
- **不建议**：纯本地单机（无法多用户多设备）、公网直裸 8501（无认证+无 HTTPS，违规且危险）。
