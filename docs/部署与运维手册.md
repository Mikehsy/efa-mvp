# 部署与运维手册（含上线与回滚 SOP）

- 版本：`v1.0.0-dev`｜编制：2026-11-13
- 适用：Windows 10 / 11，单机或局域网单实例，**同一时刻只允许 1 处写入**
- 配套：`docs/配置项说明.md`、`docs/已知限制.md`、`docs/范围与验收标准签字版.md`

## 1. 环境要求与目录

| 项 | 要求 |
| --- | --- |
| Python | 3.11 或 3.12（实测 3.12.10），安装时勾选 `Add python.exe to PATH` |
| 依赖 | 以 `requirements.lock`（37 个包精确版本）为准；直接依赖 Streamlit 1.67.0 / pandas 2.3.3 / plotly 5.24.1 |
| 端口 | 8501（`.streamlit/config.toml` 可改，或 `run.ps1 -Port 8502`） |
| 磁盘 | 数据 + 快照 + 日志 + 备份，建议预留 ≥ 1 GB |
| 关键目录 | `data/`（3 个 CSV 与 `.snapshots/`）、`backups/`、`logs/`、`scripts/`、`docs/` |

## 2. 首次部署

## 3. 日常运维

| 操作 | 命令 | 说明 |
| --- | --- | --- |
| 启动 | `.\scripts\run.ps1` | 后台启动，自动健康探活；`-Foreground` 可前台调试；`-AllowDemoData` 仅开发用 |
| 停止 | `.\scripts\stop.ps1` | 停止 8501 进程并清理残留写锁 |
| 健康检查 | `.\scripts\healthcheck.ps1` | 探活 `/_stcore/health` + 首页 200，结果写 `logs/health.log` |
| 立即备份 | `.\scripts\backup.ps1 -Label before_upgrade` | 3 个 CSV + `manifest.json` 到 `backups/` |
| 查看备份 | `.\scripts\restore.ps1 -List` | 标注完整 / 不完整 |
| 恢复 | `.\scripts\restore.ps1 -BackupDir <目录>` | 先校验、自动备份当前状态、再原子替换 |
| 回归测试 | `.\scripts\run_tests.ps1` | 47 个用例，隔离目录运行 |
| 回滚 | `.\scripts\rollback.ps1 -PreviousDir <上一版本目录> -BackupDir <备份目录>` | 见第 6 节 |

**自动保护**：每次写 CSV 前生成 `data/.snapshots/<时间戳>/` 快照（保留 20 份）；清空数据、恢复备份前自动生成整份备份（保留 30 份）。

## 4. 覆盖升级步骤

1. `.\scripts\backup.ps1 -Label before_upgrade`，并把备份**异地另存一份**。
2. `.\scripts\stop.ps1`。
3. 覆盖代码文件（`app.py`、`utils.py`、`config.py`、`logging_config.py`、`reports.py`、`pages/`、`scripts/`）；**不要覆盖 `data/`、`backups/`、`logs/`**。
4. 如依赖有变化，执行 `.\scripts\setup.ps1`（或 `-Offline`）。
5. `.\scripts\run.ps1` —— 首次访问时 `ensure_files()` 自动完成旧格式迁移（实测 7 列 → 8/14 列，运动项目回填 100%）。
6. `.\scripts\run_tests.ps1` + `.\scripts\healthcheck.ps1`，并人工抽检 3 名运动员成绩单。

> 旧 192 条记录前 7 列在迁移前后逐格不变；已有非空「运动项目」快照一律保留。

## 6. 回滚方案

**触发条件**：任一 S1 缺陷、数据不一致、健康探活连续 3 次失败、报告结论错误、BIZ 判定不可用。

```powershell
.\scripts\rollback.ps1 -PreviousDir "C:\backup\app_v0.9.0" -BackupDir "C:\...\backups\<上线前备份>"
```

脚本依次执行：停服务 → 恢复数据备份（`restore.ps1` 会先校验并二次备份当前状态）→ 用上一版本目录的 `.venv` 启动（数据目录仍指向当前 `data/`）→ 健康探活。

- **RTO ≤ 15 分钟**；**RPO ≤ 1 次写入**（每次写入前快照 + 上线前全量备份）。
- 上一版本目录必须是**完整项目副本且包含 `.venv`**，上线前不得删除。
- 同版本回滚演练已于 2026-11-13 通过；跨版本演练须在上线前用真实上一版本目录复演一次。
- 回滚后填写缺陷台账并复盘，冻结窗口内仅允许 S1 修复。

## 7. 监控与反馈

| 项 | 做法 |
| --- | --- |
| 探活 | Windows 计划任务每 5 分钟执行 `.\scripts\healthcheck.ps1`，结果追加 `logs/health.log`；连续 3 次失败即群内告警 |
| 日志 | `logs/app.log`（异常堆栈，按 5 MB 轮转保留 10 份）、`logs/audit.log`（每次写操作）、`logs/health.log` |
| 每日检查 | ERROR 日志计数、3 个 CSV 行数 / 大小基线、磁盘剩余 ≥ 1 GB、备份文件按日生成 |
| 反馈渠道 | 现场 / 群内《问题登记表》（复现步骤、截图、日志 ID、影响面），或填 `docs/缺陷台账模板.csv` |
| 响应 SLA | S1：2 小时内响应并评估回滚；S2：1 个工作日；S3：纳入下迭代 |
| 观察期 | 上线后 3 个工作日每日 17:00 简报，第 4 日复盘与验收签字，补丁窗口 `v1.0.1` |

计划任务示例（管理员 PowerShell，路径按实际修改）：

```powershell
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\...\scripts\healthcheck.ps1"'
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName 'EFA-HealthCheck' -Action $action -Trigger $trigger -Force
```

## 8. 故障处理速查

| 现象 | 处理 |
| --- | --- |
| 端口被占用 | `.\scripts\stop.ps1`，或 `run.ps1 -Port 8502` |
| 提示「另一处正在写入」 | 等待后重试；超过 30 秒的残留锁会被自动清理，也可 `stop.ps1` 清锁 |
| CSV 损坏 / 编码错误 | 页面会提示；用 `restore.ps1 -List` 选最近完整备份恢复 |
| 得分显示 `—` | 标准组未配置阈值或项目为 FMS / 描述项；到「04 评分标准」补齐 |
| 误清空数据 | `backups/*_before_clear/` 或 `data/.snapshots/` 中恢复 |
| 服务启动即退出 | 看 `logs/streamlit_err.log`；`setup.ps1 -Check` 核对依赖 |
| 浏览器看不到堆栈 | 生产 `client.showErrorDetails=false`；完整堆栈在 `logs/app.log`，调试时可临时改 `true` |
