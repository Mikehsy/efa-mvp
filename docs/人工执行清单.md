# 人工执行清单（开发侧无法代做）

> 适用范围：运动员体能与功能评估系统（EFA）v1.0.0 交付后，需要**你本人（或业务/IT）线下完成**的全部事项。
> 代码、文档、测试、部署脚本均已由开发侧完成；本清单只列「人/环境/数据/账号」相关、必须由你执行的部分。
> 涉及账号注册、权限申请、密钥配置、外部平台操作、线下验证的步骤，均在「前置条件 / 注意事项」中明确标注。

---

## 0. 整体执行顺序概览

| 阶段 | 步骤 | 关键产物 | 阻塞关系 |
| --- | --- | --- | --- |
| **A. 环境与数据准备** | 1 → 2 → 3 → 4 | 可运行环境 + 实测常模 + 正式名单/历史数据 | 步骤 3、4 是上线前置，缺一则得分口径/数据不可用于正式结论 |
| **B. 本地验收** | 5 | 浏览器确认界面无错乱、路径正确 | 依赖 A 完成 |
| **C. 网络与运维** | 6 → 7 | 局域网访问 + 健康探活 | 步骤 6 需 IT 放行；步骤 7 需管理员权限 |
| **D. 上线与观察** | 8 → 9 → 10 | 签字/tag + 发布备份 + 3 日观察 | 依赖 A/B/C；步骤 9 需保留上一版本完整目录用于回滚 |

> 建议顺序：**先在单台电脑完成 1–5 做本地验收 → 再处理 6–7 的IT/管理员事项 → 最后走 8–10 上线**。步骤 3、4 的数据采集可与 1–2 并行准备。

## A. 环境与数据准备

### 步骤 1：本地运行环境搭建（仅在换机器/新部署时需要）

- **任务名称**：搭建 EFA 运行环境
- **目的说明**：在目标机器上让系统可启动、可访问。
- **具体操作指引**：
  1. 将项目源码（含 `data/`、`scripts/`、`.venv` 可选）拷贝到目标机器；或克隆仓库。
  2. 安装 Python 3.11+（Windows 64 位，勾选「Add to PATH」）。
  3. 在项目根目录执行：`.\.venv\Scripts\Activate.ps1`（若随包带 `.venv`）；否则新建并 `python -m venv .venv` 后 `pip install -r requirements.txt`。
  4. 运行 `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Check` 检查路径与依赖。
  5. 启动 `powershell -ExecutionPolicy Bypass -File scripts\run.ps1`，浏览器打开 `http://localhost:8501`。
- **所需工具 / 账号**：目标电脑（Windows 10/11 64 位）、Python 3.11+、PowerShell 5.1+、浏览器、可联网（首次装包）。
- **预计耗时**：20–40 分钟（首次联网装依赖较慢）。
- **完成标准 / 验收方式**：`setup.ps1 -Check` 无报错；`http://localhost:8501` 首页正常渲染；控制台/日志显示健康 `ok`。

### 步骤 2：浏览器兼容性与 UI 验收（必做，线下验证）

- **任务名称**：真实浏览器验收界面
- **目的说明**：确认图标、表格、标题层级、间距在实际浏览器中一致，无 1px 塌陷或文字截断。
- **前置条件**：步骤 1 服务已启动。
- **具体操作指引**：
  1. 用最新版 **Chrome 或 Edge** 打开 `http://localhost:8501`。
  2. 依次点击侧边栏 6 个入口：🏅 主页 / 👥 运动员管理 / 📏 测试与评估 / 📊 数据分析 / ⚙️ 评分标准 / 📝 分析报告。
  3. 在「📝 分析报告」切换到「个体模式」查看表格边框、表头底色、斑马纹。
  4. 调整浏览器窗口宽度（宽屏/笔记本屏）各看一次，确认指标卡不被省略号截断。
- **所需工具 / 账号**：浏览器（无系统账号，系统本身无登录体系）。
- **预计耗时**：15 分钟。
- **完成标准 / 验收方式**：6 页顶部 hero 图标与标题同行对齐；侧边栏 6 个入口图标风格统一；报告表格有边框/表头/斑马纹；无任何元素被压成竖条。若某处需微调，把页面名与截图反馈开发侧。
- **注意事项**：headless 截图在本机只能截到 Streamlit 加载骨架，**必须以你本地真实浏览器为准**。

### 步骤 3：替换实测常模（最关键，素材上传 / 数据导入）

- **任务名称**：用队内实测阈值替换示例常模
- **目的说明**：当前 `STANDARDS_VERSION = "示例常模 v0（待队内实测替换）"`，所有得分都是示例口径；替换为实测 216 组阈值后，得分/达标率才可用于正式结论。
- **前置条件**：
  - 已完成队内实测数据采集（参考 `docs/常模数据采集模板.csv` 的 216 组结构）。
  - **未替换前禁止对外出具任何评分结论。**
- **所需工具 / 账号**：Excel / 任意 CSV 编辑器；或系统「⚙️ 评分标准」页面（无需额外账号）。
- **具体操作指引**（二选一）：
  - **方式 A（文件替换，推荐批量）**：备份 `data/standards.csv` → 按 `data/standards.csv` 的 10 列表头填写实测值 → 以 **UTF-8（建议带 BOM）** 保存并覆盖原文件 → 改 `config.py` 中 `STANDARDS_VERSION = "2026Q4-实测"`（或你的版本号）→ 重启服务。
  - **方式 B（页面编辑）**：进入「⚙️ 评分标准」页逐项编辑阈值并保存；仍可点击「恢复内置示例标准」回退。改完记得同步 `config.py` 的版本号并重启。
- **预计耗时**：数据整理 1–2 天；系统操作 30 分钟。
- **完成标准 / 验收方式**：侧边栏与报告头部显示新常模版本号；抽查某测试项目，修改阈值前后得分随之变化；`⚙️ 评分标准` 页「待配置组合数」为 0。
- **注意事项**：CSV 编码必须为 UTF-8，否则中文乱码；覆盖前务必备份，误改可用备份或「恢复内置示例标准」还原。

### 步骤 4：导入正式名单与历史测试数据（素材上传 / 数据导入）

- **任务名称**：导入运动员名单与历史测试记录
- **目的说明**：用正式数据替换演示数据，使「运动员管理」「测试与评估」反映真实队伍。
- **前置条件**：
  - 已按模板整理数据：`data/athletes.csv`（8 列：`运动员ID, 姓名, 性别, 出生日期, 所属队伍, 专项, 备注, 运动项目`）、`data/tests.csv`（14 列：`记录ID, 运动员ID, 测试日期, 测试项目, 成绩, 单位, 备注, 测试类别, 评分类型, 侧别, 标准组, 测试时年龄, 疼痛标记, 运动项目`）。
  - **`运动项目` 为必填**，空值会被校验拦截。
- **所需工具 / 账号**：Excel（无系统账号）。
- **具体操作指引**：
  1. 先复制整个 `data/` 文件夹做备份。
  2. 按上述表头在 Excel 填写，**保存为 UTF-8 CSV（带 BOM 推荐）**，覆盖 `data/athletes.csv` 与 `data/tests.csv`。
  3. 建议先小批量（1–2 条）试导入，确认无乱码与校验报错后，再全量替换。
  4. 重启服务后核对。
- **预计耗时**：数据整理 0.5–1 天；导入与核对 10 分钟。
- **完成标准 / 验收方式**：「运动员管理」显示正式名单；「测试与评估」有历史记录；无空 `运动项目`；得分/达标率基于步骤 3 的实测常模重算。
- **注意事项**：编码错误会乱码；ID 重复或外键缺失会被写入校验拦下。

## B. 本地验收

### 步骤 5：文件路径调整（换目录 / 换机器时）

- **任务名称**：确认数据与日志目录指向
- **目的说明**：当项目不在默认路径、或希望数据与程序分离时，把数据/备份/日志指到实际位置。
- **具体操作指引**：
  - 默认即用项目内 `data/`、`backups/`、`logs/`，无需改动。
  - 如需自定义，设置环境变量 `EFA_DATA_DIR`、`EFA_BACKUP_DIR`、`EFA_LOG_DIR` 指向目标目录，再运行 `scripts\setup.ps1 -Check`。
- **所需工具 / 账号**：系统环境变量设置权限（本机用户即可）。
- **预计耗时**：5 分钟。
- **完成标准 / 验收方式**：`setup.ps1 -Check` 显示三个目录路径正确且可写；服务启动后读写落在指定目录。
- **注意事项**：自定义目录需确保服务进程对该目录有读写权限（尤其计划任务以 SYSTEM/其他账户运行时）。

## C. 网络与运维

### 步骤 6：局域网 / 外部访问配置（可选，需 IT 配合）

- **任务名称**：开放多人访问
- **目的说明**：让同网段同事能访问系统。
- **前置条件**：
  - **IT 部门允许**在内网开放 8501 端口。
  - 明确：**系统无账号/权限体系**，任何能访问地址的人都能读写数据，故仅限内网 + 防火墙白名单。
- **所需工具 / 账号**：文本编辑器（改 `.streamlit/config.toml`）；**Windows 防火墙高级设置权限（需 IT/管理员）**。
- **具体操作指引**：
  1. 编辑 `.streamlit/config.toml`，将 `[server]` 下 `address = "localhost"` 改为 `address = "0.0.0.0"`。
  2. 在 Windows 防火墙入站规则中放行 TCP 8501（建议限制来源 IP 段）。
  3. 重启服务，同事用 `http://<你的内网IP>:8501` 访问。
- **预计耗时**：10–20 分钟（取决于 IT 审批）。
- **完成标准 / 验收方式**：同网段另一台机器可打开页面并正常操作。
- **注意事项**：
  - **禁止直接公网暴露**：无认证，公网开放有数据泄露风险。如必须对外，需额外加反向代理 + 登录认证（属开发任务，不在本清单）。
  - 公网/域名/服务器部署涉及**外部平台账号（云厂商/内网服务器权限）**，需你方自行申请，开发侧可提供部署手册支持。

### 步骤 7：注册监控探活计划任务（需管理员权限）

- **任务名称**：注册健康探活定时任务
- **目的说明**：服务异常时自动发现并便于群内告警。
- **前置条件**：以**管理员身份**运行 PowerShell；EFA 服务持续运行。
- **所需工具 / 账号**：Windows 任务计划程序 / 管理员 PowerShell（属线下运维权限）。
- **具体操作指引**：按 `docs/部署与运维手册.md` 第 7 节命令，注册名为 `EFA-HealthCheck` 的计划任务，每 5 分钟执行 `scripts\healthcheck.ps1`。
- **预计耗时**：15 分钟。
- **完成标准 / 验收方式**：`logs/health.log` 每 5 分钟新增一行 `health=True`；手动停掉服务后探活返回非零（可在告警通道验证）。
- **注意事项**：计划任务运行账户需对 `logs/` 有写权限，且能访问 `http://localhost:8501/_stcore/health`。

## 常见问题与排查建议

**Q1：浏览器打不开 `http://localhost:8501`？**
- 检查服务是否在运行（`scripts\stop.ps1` / `run.ps1`）；确认端口 8501 未被占用；本机防火墙是否拦截。用 `curl http://localhost:8501/_stcore/health` 看是否返回 `health=True`。

**Q2：页面/数据中文乱码？**
- 所有 CSV 必须以 **UTF-8（带 BOM 推荐）** 保存；Excel 另存为「CSV UTF-8（逗号分隔）」即可。`athletes.csv` / `tests.csv` / `standards.csv` 三者编码一致。

**Q3：得分或达标率看起来不对？**
- 确认步骤 3 已替换实测常模，且 `config.py` 的 `STANDARDS_VERSION` 已更新并**重启服务**。未替换前为示例常模，仅用于演示。

**Q4：表格/图表被压成竖条（1px）？**
- 该问题已在代码中统一修复（`width="stretch"`）。若在新环境复现，见 `docs/已知限制.md` 与防回归测试 `tests/test_layout.py`；并反馈开发侧。

**Q5：多人访问时报权限/访问不了？**
- 见步骤 6：确认 `config.toml` 的 `address` 已改、防火墙已放行且来源 IP 在白名单；系统本身无登录账号，切勿公网暴露。

**Q6：需要账号体系 / 单点登录 / 邮件或云存储集成？**
- 当前系统**无账号体系、无外部 API 密钥**。若需 SSO、邮件告警、对象存储等，涉及**外部平台账号注册、权限申请与密钥配置**，属开发侧新增需求，不在本交付范围内，需另行排期。

**Q7：换机器后数据没了？**
- 数据在 `data/`（或 `EFA_DATA_DIR` 指定目录）。换机器时连同 `data/`、`backups/`、`logs/` 一起迁移，或用步骤 9 的备份恢复。
