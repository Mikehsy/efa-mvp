# PIPL 合规实施说明（云端账号版）

- 适用版本：政策版本 `2026-11-18-v1`
- 适用形态：Streamlit Community Cloud + Supabase PostgreSQL（`EFA_USE_DB=1`）
- 依据：《中华人民共和国个人信息保护法》（PIPL）第 13、14、15、16、17、23、28–31、38、39、44–50、51、55 条

> ⚠️ **边界声明**：本文档记录的是**已落地的技术措施**。代码不能使服务自动满足全部法律义务。
> 运营方仍须完成第八节列出的法律与组织措施，并经法务审阅后方可宣称合规、正式商用。
> 系统在任何页面都不会显示「已合规」字样；运营方信息未配置时会持续显示警示。

## 一、已落地的技术措施

| 措施 | 实现位置 | 对应要求 |
| --- | --- | --- |
| 注册时展示完整隐私政策并要求逐项同意 | `utils._db_auth_gate()`、`privacy.policy_text()` | 第 14、17 条：知情、自愿、明确 |
| 敏感个人信息**单独同意** | `privacy.CONSENT_ITEMS["sensitive"]` | 第 29 条 |
| 个人信息出境**单独同意**并披露接收方与区域 | `privacy.CONSENT_ITEMS["cross_border"]`、政策第四节 | 第 39 条 |
| 不满 14 周岁运动员监护人同意确认 | `privacy.CONSENT_ITEMS["minor"]`、政策第六节 | 第 31 条 |
| 同意事件持久化（版本、同意项、时间、动作） | `db.consents` 表、`db.record_consent()` | 第 13、14 条：可追溯 |
| 留痕去标识化（只存 `owner_hash`） | `privacy.owner_hash()` | 第 51 条：最小必要 |
| 政策版本化 + 变更强制重新同意 | `auth.consent_status()`、`utils._privacy_gate()` | 第 14 条：变更需重新同意 |
| 历史账号（升级前注册）强制补同意 | `auth.CONSENT_MISSING` → 重新同意界面 | 合法性基础补正 |
| 撤回同意后停止处理、账号停用 | `auth.withdraw_consent()`、`db.set_user_status()` | 第 15、16 条 |
| 撤回后仍可行使删除权，无需先重新同意 | `utils._render_reconsent()` 中的删除入口 | 第 47 条：权利不得被设置障碍 |
| 查阅 / 复制 / 可携带导出（JSON，完整与脱敏） | `auth.collect_personal_data()`、`privacy.build_export()` | 第 45 条 |
| 导出剔除密码哈希与盐 | `privacy.build_export()` | 第 51 条 |
| 注销即删除账号信息与全部业务数据 | `auth.delete_account()`、`db.delete_account_data()` | 第 47 条 |
| 保存期限可查询、不自动删除 | `db.last_data_write()`、`db.expired_owner_ids()` | 第 19 条：最短必要期限 |
| 同意闸门先于任何业务数据读写 | `utils.require_access_gate()` | 第 16 条：不同意不得处理 |
| 文件审计 + 数据库留痕双写 | `logging_config.audit()`、`auth._trace()` | 第 51 条 |

### 数据库变更

新增 `consents` 表（随 `_ensure_schema()` 自动创建，无需手工迁移脚本）：

| 列 | 说明 |
| --- | --- |
| `id` | 自增主键，`BIGSERIAL` / `INTEGER AUTOINCREMENT` |
| `owner_hash` | SHA-256(盐 + 账号 ID)，**不含**用户名、邮箱等直接标识 |
| `policy_version` | 同意时适用的政策版本 |
| `items` | JSON 数组，记录勾选的同意项 |
| `action` | `grant` / `withdraw` / `delete` |
| `ts` | 本地时间 ISO 字符串 |
| `detail` | 事件说明（注册、重新同意、撤回、注销） |

`idx_consents_owner(owner_hash, id)` 索引用于按账号查询历史。
账号注销时**不删除**该表记录——它已去标识化，作为处理活动合法性的证明依法留存。

## 二、处理的个人信息清单

| 类别 | 字段 | 敏感性 |
| --- | --- | --- |
| 账号信息 | 用户名、邮箱（选填）、密码 PBKDF2-SHA256 哈希与随机盐、注册时间、状态 | 一般 |
| 运动员档案 | 姓名、性别、出生日期、所属队伍、专项、运动项目、备注 | 出生日期等按敏感信息从严处理 |
| 测试与评估 | 成绩、日期、单位、侧别、标准组、测试时年龄、FMS 疼痛标记、备注 | 健康与体能相关信息，敏感 |
| 评分标准配置 | 达标线、优秀线、单位、方向 | 一般（配置数据） |
| 合规留痕 | `owner_hash`、政策版本、同意项、动作、时间 | 去标识化 |

系统不收集身份证号、生物识别、行踪轨迹、金融账户等信息。

## 三、同意机制的运行逻辑

1. **注册**：`_db_auth_gate()` 展示政策全文与 4 个勾选项；`auth.register(consents=...)` 校验
   `privacy.consent_valid()`，缺任一项即拒绝注册并提示。注册成功后写入 `grant` 事件。
2. **每次会话**：`inject_css()` → `require_access_gate()` → `_privacy_gate()` 先校验同意，
   通过后才执行 `ensure_files()` 和业务读写。校验结果按
   `(用户 ID, 政策版本)` 缓存在 `session_state`，避免每次 rerun 查库。
3. **需要重新同意的三种情况**：
   - `missing`：无任何同意记录（合规功能上线前注册的历史账号）；
   - `version`：`EFA_POLICY_VERSION` 变更；
   - `withdrawn`：用户主动撤回同意。
4. **重新同意界面**（所有页面统一展示，不依赖用户能否进入业务页面）：政策全文、
   4 个勾选项、重新同意按钮、退出登录、**直接删除账号与数据**按钮。
5. **撤回同意**：写入 `withdraw` 事件并把 `users.status` 置为 `withdrawn`。
   `auth.login()` 仍允许验证密码（否则无法行使重新同意或删除权），但闸口会阻止访问业务数据。

> 升级影响：部署后**所有已有账号首次登录都会被要求重新同意一次**，这是政策首次生效
> 所必需的补正，属预期行为。应提前通知用户。

## 四、用户权利操作路径（「🔒 隐私与账号」页）

| 权利 | 入口 | 结果 |
| --- | --- | --- |
| 查阅、复制 | 「下载完整个人数据（JSON）」 | 账号信息（无密码凭据）、档案、测试记录、评分标准、同意记录 |
| 脱敏副本 | 「下载脱敏副本（JSON）」 | 姓名、备注、用户名、邮箱部分遮蔽，便于对外提供 |
| 更正 / 补充 | 各业务页面直接编辑 | 即时生效 |
| 撤回同意 | 「撤回同意并停用账号」（勾选确认） | 停止处理，账号停用 |
| 重新同意 | 闸口自动展示的表单 | 恢复使用 |
| 删除 / 注销 | 「永久删除账号与全部数据」（输入用户名确认） | 删除 `users` 与 `user_data` 中该账号全部记录 |
| 解释处理规则 | 页面内政策全文 | 单一来源 `privacy.policy_text()` |

投诉与咨询渠道：政策中显示的 `EFA_PRIVACY_CONTACT`，承诺 15 个工作日内答复。

## 五、保存期限与清理 SOP

- 期限：自账号最后一次写入业务数据起 `EFA_RETENTION_DAYS` 天（默认 730）。
- 起算点查询：`db.last_data_write(owner_id)`；到期账号清单：`db.expired_owner_ids(days)`。
- **刻意不做自动删除**：删除个人信息不可逆，须由运营方按 PIA 结论复核后执行
  `auth.delete_account(owner_id)`，并留下去标识化记录。
- 建议 SOP：每季度导出到期清单 → 运营方复核是否仍在服务期 → 书面确认 → 执行删除 →
  记录执行时间、执行人、账号条数 → 归档。
- 注：`expired_owner_ids()` 仅覆盖写过业务数据的账号；从未写入数据的账号不会被列出，
  需另行按 `users.created_at` 人工复核。

## 六、配置项

在 Streamlit Cloud → App settings → Secrets 中配置（模板见
`.streamlit/secrets.toml.example`）；本地回退同名环境变量。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `EFA_OPERATOR_NAME` | `【待填写：运营主体全称】` | 必填，真实处理者名称 |
| `EFA_PRIVACY_CONTACT` | `【待填写：个人信息保护负责人邮箱/电话】` | 必填，权利受理渠道 |
| `EFA_RETENTION_DAYS` | `730` | 保存期限（天） |
| `EFA_OVERSEAS_REGION` | `东北亚（东京）` | 数据库区域，展示于政策第四节 |
| `EFA_POLICY_VERSION` | `2026-11-18-v1` | 变更即触发全员重新同意 |
| `EFA_POLICY_EFFECTIVE_DATE` | `2026-11-18` | 政策正文展示的生效日期，变更版本时须同步更新 |
| `EFA_PRIVACY_HASH_SALT` | `efa-pipl-v1` | 去标识化盐值，上线前设定随机值且**不得中途更改** |

`privacy.operator_configured()` 检测前两项是否仍为占位符；未配置时注册页、
重新同意页、隐私页均显示警示，但不阻断试用。

## 七、部署与验收

### 需上传/更新的文件

- 根目录：`db.py`、`auth.py`、`utils.py`、`privacy.py`（新建）
- `pages/`：`6_🔒隐私与账号.py`（新建，**必须进入 `pages/` 目录再上传**）
- 文档 / 配置：`docs/PIPL合规实施说明.md`、`.streamlit/secrets.toml.example`
- 测试：`tests/test_pipl.py`

上传后在 Streamlit Cloud 填入第六节 Secrets → `Save` → `Reboot app`。
数据库表由 `_ensure_schema()` 自动创建，无需手工执行 DDL。

### 验收步骤

1. `python -m unittest discover -s tests -q` 全绿（含 9 项 PIPL 测试）。
2. 新账号注册：不勾选 → 被拒绝；全部勾选 → 成功。
3. 登录后侧栏出现「隐私与账号」；导出 JSON，检查无 `password_hash` / `salt`。
4. 撤回同意 → 页面立即变为「重新同意」，业务数据不可访问；重新勾选 → 恢复。
5. 用**升级前已存在的账号**登录 → 应被要求补同意。
6. 改 `EFA_POLICY_VERSION` 后 Reboot → 全员被要求重新同意。
7. 注销（输入用户名确认）→ 该账号无法再登录；用另一个账号登录确认数据不串。
8. 查 `consents` 表：注销账号仍有 `delete` 留痕，且不含用户名、邮箱、姓名。

## 九、已知局限

- **未成年人**：系统不向不满 14 周岁个人直接提供注册，但教练录入时仅做「已取得监护人同意」的
  自我确认，未核验证明文件，也未实现专门的未成年人处理规则；由运营方线下落实。
- **审计日志**：`logs/audit.log` 写在应用容器内，重启可能丢失；关键合规事件已同时写入
  `consents` 表，但业务写操作的审计日志仍不具备长期留存能力。
- **去标识化 ≠ 匿名化**：`owner_hash` 由账号 ID 加盐哈希得到。若盐值泄露且 ID 可枚举，
  存在重识别可能；务必使用高熵盐值并限制数据库访问。
- **脱敏副本**：`mask=True` 只遮蔽姓名、备注、用户名、邮箱；出生日期、所属队伍、成绩等
  字段仍可能构成间接标识，对外提供前须人工复核。
- **跨境**：当前部署形态必然涉及境外存储，第 38 条合法路径未由代码解决。
- **多租户**：数据按个人账号 `owner_id` 隔离，尚非「按队共享 + 角色权限」的租户模型。
- **无须同意的情形**：政策声明处理为提供服务所必需，未提供「拒绝后仅使用不含个人信息功能」的
  降级路径；如业务上需要，应另行设计。
