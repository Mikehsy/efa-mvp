# 浏览器自动巡检配置说明

- 目标：让 Workbuddy / 自动化任务能自动打开应用、使用专用测试账号登录、截图并归档。
- 工具：`agent-browser` + 本机 Chrome/Edge
- 安全原则：账号密码只放本地 `.ops/browser.env` 与 agent-browser 的加密 Auth Vault，不入库、不发聊天、不放公开仓库。

## 2. 登录方式（首选 Auth Vault）

巡检脚本的登录优先级：

| 顺序 | 方式 | 命令 | 需要手工找选择器 |
| --- | --- | --- | --- |
| 1 | Auth Vault | `agent-browser auth login efa-ops` | 不需要，工具自动识别表单 |
| 2 | 手动选择器兜底 | `fill/click @e1 @e2 @e3` | 需要 |

Auth Vault 由 agent-browser 自己等待表单字段出现、校验可见性，再填值并提交。
凭据加密保存在 `%USERPROFILE%\.agent-browser\auth\efa-ops.json`
（密钥为同目录上一级的 `.encryption-key`），不在本仓库内。

## 3. 首次配置

### 3.1 创建本地配置文件

在项目根目录执行：

```powershell
New-Item -ItemType Directory -Force -Path .ops | Out-Null
Copy-Item ops\browser.env.example .ops\browser.env
notepad .ops\browser.env
```

填写（`EFA_APP_URL` 必须是可访问的完整地址，不要粘贴带分支名的界面文字）：

```text
EFA_APP_URL=https://efa-mvp-e3vgfxis7szkghhe6d4for.streamlit.app/~/+/?embed=true
EFA_OPS_USERNAME=专用测试账号
EFA_OPS_PASSWORD=专用测试密码
EFA_AUTH_PROFILE=efa-ops
EFA_LOGIN_USER_SELECTOR=
EFA_LOGIN_PASS_SELECTOR=
EFA_LOGIN_SUBMIT_SELECTOR=
```

> ⚠️ **地址必须带 `/~/+/?embed=true`**，不能只用 `https://xxx.streamlit.app`。
> Streamlit Community Cloud 的默认页面会把应用装进一个 `streamlitApp` iframe，
> 主文档里 `input` 数量为 0，agent-browser 的 CSS 选择器和自动表单识别都会全部落空
> （实测报 `Timed out waiting for username field`）。
> 改成 Cloud 的直连代理路径 `/~/+/?embed=true` 后，表单元素回到主文档，自动识别即可命中，
> 同时页面上不再有 `Fork`/`source` 等 Cloud 工具栏，截图更干净。
>
> 获取方法：先打开根地址，在页面里读一次 iframe 的 `src`：
>
> ```powershell
> agent-browser --session probe eval "document.querySelectorAll('iframe')[0].src"
> ```
>
> 输出形如 `https://xxx.streamlit.app/~/+/?embed=true`，直接拿来用。

> 当前使用 `adminbot` —— 它是为本系统自动化巡检**专门注册的账号**，不是管理员账号；
> 只往里放脱敏测试数据，名称里的 admin 不代表权限。不要拿真实管理员账号来跑巡检。

### 3.2 一次性写入 Auth Vault

```powershell
powershell -ExecutionPolicy Bypass -File scripts\ops_auth_setup.ps1
```

脚本行为：

- 从 `.ops/browser.env` 读取地址与账号密码；
- 调用 `agent-browser auth save`，写入加密的 Auth Vault；
- 日志里密码值自动替换成 `***`，终端只打印 URL / 用户名等元数据；
- 已存在同名 profile 时不会覆盖，需要覆盖请加 `-Force`。

常用参数：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\ops_auth_setup.ps1 -Show      # 查看现有 profile 元数据
powershell -ExecutionPolicy Bypass -File scripts\ops_auth_setup.ps1 -Force     # 覆盖重建
powershell -ExecutionPolicy Bypass -File scripts\ops_auth_setup.ps1 -Delete    # 删除 profile
```

> ⚠️ **不要用 `--password-stdin`（本机实测有 bug）**
> 在 Windows 上，`agent-browser auth save --password-stdin` 会把密码多存一个字符：
> 10 位存成 11 位、20 位存成 21 位。管道、`StreamWriter`、裸字节流三种写法结果一致，属于 CLI 侧行为。
> 后果是登录必然报「用户名或密码错误」，而且从配置文件里完全看不出问题。
> 因此脚本改用 `--password` 传参，并靠日志脱敏（`***`）避免密码落盘。
> 复核方法：登录后读一次密码框长度，应与配置一致。
>
> ```powershell
> agent-browser --session chk eval "(function(){var i=document.querySelectorAll('input');return i[1].value.length})()"
> ```

### 3.3 正式跑一次登录截图

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cloud_ops_capture.ps1
```

成功时输出（**默认不保留证据目录**）：

```text
EVIDENCE_DIR=(已清理)
LOGIN_METHOD=auth-vault:efa-ops
LOGIN_RESULT=ok
PAGE_CHECK=ok
```

`PAGE_CHECK` 是删除证据前的最后一次页面体检：在页面正文里找 `Traceback`、`ModuleNotFoundError`、
`ImportError`、`AttributeError`、`KeyError`、`TypeError`、`Uncaught`。命中就返回 `ERROR:<原文>`，
没命中返回 `ok`。因为证据不留档，这个字段是事后唯一能说明"页面本身有没有崩"的依据。

证据策略：

| 情形 | 结果 |
| --- | --- |
| 成功 | 删除本次 `ops-evidence/<时间戳>/`，只输出结论 |
| 失败 | 保留到 `ops-evidence\last-failure\`（固定名，每次覆盖，不累积） |
| 加 `-KeepEvidence` | 按时间戳目录留档 |
| 显式 `-EvidenceDir <路径>` | 尊重指定路径，不自动删除 |

需要留档查看截图时：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cloud_ops_capture.ps1 -KeepEvidence
```

留档时才会生成：

```text
ops-evidence/<时间戳>/
├── 00_login_snapshot.txt
├── 01_app_home.png
├── 02_after_login.png
├── 03_after_login_snapshot.txt
├── 04_login_method.txt
└── agent_browser.log
```

`04_login_method.txt` 记录本次实际用的登录方式与结果（含 `LOGIN_RESULT`）：
`ok`（已进入应用）、`rejected`（提交了但被应用拒绝）、`skipped`（`-SkipLogin`）。

`auth login` 返回 0 只代表"找到了表单并提交成功"，不代表登录被接受。脚本提交后会再取一次页面状态：
登录 tab 的用户名框是否仍在、页面是否出现「用户名或密码错误」等提示，任一命中即判 `rejected` 并让脚本以非 0 退出，
避免把一张"仍停在登录页"的截图当成巡检通过。

## 4. 仍在手工维护选择器时的兜底路径

只有在 Vault 登录失败、或需要排查登录页结构时才用。

1. 跳过登录抓登录页快照：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cloud_ops_capture.ps1 -SkipLogin
```

2. 打开 `00_login_snapshot.txt`，找到用户名输入框、密码输入框、登录按钮的 `@e编号`，填入 `.ops/browser.env`：

```text
EFA_LOGIN_USER_SELECTOR=@e1
EFA_LOGIN_PASS_SELECTOR=@e2
EFA_LOGIN_SUBMIT_SELECTOR=@e3
```

3. 强制走手动路径验证：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cloud_ops_capture.ps1 -ManualLogin
```

说明：

- Vault 登录失败时脚本会自动回退到该路径（需先填好三个选择器），并在 `04_login_method.txt` 记为 `LOGIN_METHOD=manual-selectors`。
- 手动路径下密码会出现在 `agent_browser.log` 吗？不会。脚本把密码值登记为敏感参数，日志中替换为 `***`。
- `@e编号` 是登录页快照的临时编号，页面改版会变化，这是优先用 Vault 的原因。

## 6. 安全边界

允许自动化：

- 打开应用；
- 用专用测试账号登录；
- 截图；
- 读取页面快照；
- 检查页面错误文本。

禁止自动化：

- 修改 Secrets；
- 修改真实运动员数据；
- 删除账号；
- 导出真实用户数据；
- 输入数据库密码或连接串；
- 使用真实管理员账号；
- 把 `.ops/browser.env` 上传到 GitHub。

`.gitignore` 已加入：

```text
.ops/
ops-evidence/
```

## 7. 故障排查

### `Timed out waiting for username field`

应用被包在 Streamlit Cloud 的 `streamlitApp` iframe 里，主文档没有任何 `input`。
把 `EFA_APP_URL` 换成 `/~/+/?embed=true` 的直连地址（见 3.1 的说明），再 `ops_auth_setup.ps1 -Force` 重建凭据。

### `登录未生效：页面提示「用户名或密码错误」`

`auth login` 已经把账号密码提交上去了，但应用拒绝了。这属于凭据问题，不是脚本问题：

- 确认该账号已在应用里注册（Streamlit 首次部署时数据库是空的，需要先注册）；
- 确认没开大写锁定、没混用全角字符；
- 改完 `.ops/browser.env` 后执行 `scripts\ops_auth_setup.ps1 -Force`，Vault 里的旧密码不会自动更新。

### `EFA_APP_URL 含空格或非 ASCII 字符`

配置里粘进了带分支名的界面文字（例如 `https://efa-mvp ∙ main ∙ app.py.streamlit.app`）。
改成真实可访问地址，形如 `https://efa-mvp.streamlit.app`。

### 用户名密码明明正确，却一直提示「用户名或密码错误」

优先怀疑 Vault 里存的密码多了一个不可见字符。2026-11-19 就踩过这个坑：
`--password-stdin` 在 Windows 上把 20 位密码存成了 21 位，导致应用拒绝登录，
而 `.ops/browser.env` 里的密码是完全正确的。

核查步骤：

```powershell
# 1) 配置里密码的真实长度（不打印密码本体）
. scripts\ops_browser_common.ps1
(Read-OpsEnvFile -Path (Join-Path $script:ProjectRoot '.ops\browser.env'))['EFA_OPS_PASSWORD'].Length

# 2) 登录后页面上密码框的实际长度，两者应相等
agent-browser --session chk eval "(function(){var i=document.querySelectorAll('input');return i[1].value.length})()"
```

不相等就 `ops_auth_setup.ps1 -Force` 重建（当前脚本已改用 `--password` 写入，不会再出现此问题）。

### 登录失败（Vault 路径）

- 先 `ops_auth_setup.ps1 -Show` 确认 profile 的 URL 与当前 `EFA_APP_URL` 同源；
- 确认账号密码仍有效（`ops_auth_setup.ps1 -Force` 重建）；
- 需要看页面结构时用 `-SkipLogin` 抓快照，再考虑手工选择器兜底。

### `Auth Vault 登录失败（exit ...），改用手动选择器兜底`

说明 Vault 已尝试但没成功（常见原因：登录页元素被替换、账号被锁、页面改版）。
此时若无手动选择器，脚本会直接报错并提示先跑 `ops_auth_setup.ps1`。

### agent-browser 找不到

脚本使用固定 Node 路径。若路径变化，更新：

```powershell
# scripts/ops_browser_common.ps1
$script:NodeDir = "C:\Users\10692\.workbuddy\binaries\node\versions\22.22.2-6"
```

### 浏览器未启动

脚本会优先使用 Chrome，找不到则使用 Edge。若两者都找不到，需重新安装浏览器。

## 8. 只读深度巡检（补充）

基础 `cloud_ops_capture.ps1` 只覆盖「打开 → 登录 → 首页快照」。需要覆盖业务页与评分抽检时，追加运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\cloud_ops_deep_check.ps1
```

该脚本严格只读：登录后在侧边栏逐个打开 6 个业务页并做页面错误体检；在「评分标准」页只读读取阈值，按三段式公式抽检握力与 30 米冲刺；并只读核对本地 HEAD / 远端 `main` / 工作区变更数。不点保存/删除/载入演示数据，不访问 Supabase 或 Streamlit 控制台，不提交或推送 Git。输出 `deep_check_report.txt` 与各页快照到 `ops-evidence/<日期>_deep/`。

Supabase 状态与 Streamlit Logs 需第三方控制台凭据并触碰生产项目，超出自动巡检边界，仍由人工执行。
