# 个人信息安全事件应急预案（模板）

- 版本：`2026-11-18-v1`
- 适用：云端 SaaS 版
- 配套：`docs/上线运维保障方案.md`、`docs/观察期问题登记表.csv`
- 说明：本文提供技术处置流程和记录模板；是否通知监管、通知个人、启动法律责任判断，必须由运营方法务决定。AI 不得代为通知、代签或作法律结论。

---

## 1. 事件分级

| 级别 | 定义 | 示例 | 响应 |
| --- | --- | --- | --- |
| P1 严重 | 可能造成大规模个人信息泄露、丢失、越权访问或业务中断 | 数据库密钥泄露、公开仓库误传 Secrets、账号串数据、数据库被删 | 立即启动应急，DEV/运维/法务同时介入 |
| P2 较高 | 影响部分用户或部分功能，但未见大规模泄露 | 某账号数据异常、报告错误、单页功能不可用 | 当日响应，限定影响范围 |
| P3 一般 | 不影响数据安全与核心功能 | 文案、布局、轻微性能问题 | 纳入补丁窗口 |

## 3. 通用处置流程

### 3.1 发现与登记

1. 记录发现时间、发现人、来源。
2. 在 `docs/观察期问题登记表.csv` 新增一条。
3. 事件编号格式：`INC-YYYYMMDD-序号`。

### 3.2 止损

根据事件类型选择：

- 密钥泄露：立刻重置 Supabase 密码、轮换 `DATABASE_URL`、撤销 GitHub PAT、更新 Streamlit Secrets。
- 公开仓库误传敏感文件：立刻删除文件并清理 Git 历史，重置所有可能泄露的密钥。
- 应用异常：进入 Streamlit Cloud `Manage app` → `Logs` 收集错误，必要时 Reboot 或回滚。
- 数据错乱：暂停相关账号写入，从最近备份恢复临时环境核验。
- 账号串数据：立即停用应用或关闭注册/写入，检查 `EFA_USE_DB` 与 `owner_id` 过滤。

### 3.3 影响评估

必须记录：

- 涉及哪些账号；
- 涉及哪些数据表；
- 是否包含敏感个人信息；
- 是否涉及未成年人；
- 是否涉及出境数据；
- 异常访问时间窗口；
- 是否可能被外部访问；
- 是否已发生导出、删除、修改。

### 3.4 证据保存

保存：

- 截图；
- 日志片段；
- GitHub commit；
- 操作时间线；
- 邮箱/工单记录；
- 恢复演练或回滚结果。

禁止在证据中直接保存完整密码、连接串、PAT、未脱敏个人数据。

### 3.5 通知判断

- 是否通知监管部门、通知个人、何时通知，由法务/隐私负责人判断。
- DEV/运维不得自行对外发布事件结论。
- 用户沟通前必须确认事实范围与口径。

### 3.6 恢复与复盘

1. 恢复服务。
2. 抽检登录、数据隔离、报告、隐私页。
3. 写复盘报告：
   - 时间线；
   - 根因；
   - 影响；
   - 已采取措施；
   - 改进项；
   - 责任人与期限。

## 4. 常见场景处置卡

### 场景 A：Supabase 连接串泄露

1. Supabase 重置数据库密码。
2. 生成新的 Session pooler 连接串。
3. 更新 Streamlit Cloud Secrets。
4. Reboot app。
5. 重置 GitHub PAT 或相关 token。
6. 搜索 GitHub 历史是否残留密钥。
7. 检查数据库近期异常连接。
8. 记录影响窗口。

### 场景 B：公开仓库误传 `secrets.toml`

1. 立即删除仓库文件。
2. 清理 Git 历史。
3. 重置所有 contained secrets。
4. 撤销 PAT。
5. 检查仓库 Fork / Clone 情况。
6. 法务评估通知义务。
7. 记录整改。

### 场景 C：账号串数据

1. 立即停用写入入口或暂停应用。
2. 检查 `EFA_USE_DB="1"`。
3. 检查所有数据读写是否按 `owner_id` 过滤。
4. 导出受影响账号数据样本脱敏核查。
5. 修复后 Reboot。
6. 用两个测试账号做隔离验收。
7. 法务评估是否属于个人信息泄露/异常暴露。

### 场景 D：误删生产数据

1. 停止相关账号继续写入。
2. 记录误删时间、账号、表。
3. 从 Supabase 备份或异地备份恢复到临时环境。
4. 核对行数与关键记录。
5. 决定是否覆盖恢复或按记录补回。
6. 记录 RPO/RTO。

### 场景 E：应用整体不可用

1. 查看 Streamlit Cloud 状态页。
2. 查看 Manage app → Logs。
3. 判断是否数据库连不上、依赖失败、Secrets 错误。
4. 能快速修复则修复后 Reboot。
5. 不能快速修复则回滚上一稳定 commit。
6. 记录停机时间。

## 6. 通过标准

满足以下条件才算 E11 有证据支撑：

- 预案已指定角色和联系方式；
- 事件分级清晰；
- 至少完成一次桌面演练；
- 演练发现的问题有整改记录；
- 法务/隐私负责人确认通知判断流程；
- 事件记录模板已归档。
